# intranet_bundle 全流程产物清单（53 条全量）

> 此清单作全量参考：demo_bundle 的 12 条子集太薄跑不动时，从这里拿丰满结果做对照/兜底。

## 两处 final_rules 的区别

| 路径 | 说明 |
|---|---|
| `runs/coldstart/merged/` | **实际跑批目录**：final_rules.json + NL + **诊断规则块 + 增强 prompt**（全） |
| `data/runs/coldstart/merged/` | seed 目录：final_rules.json + NL + 一个冒烟时的 evaluator_prompt（无 diagnostic） |

两处的 `final_rules.json` 内容相同（22 条）。

## 为什么 53 条能跑出 22 条规则，12 条跑出 0 条

- 53 条 = **badcase + goodcase 混合** → golden 有"对的样子"校准 → 判 13 条失败 → coldstart 有料 → 22 条规则。
- 12 条 = **只有 badcase、无 goodcase + 数量少** → golden 判定基准漂移、判太宽 → 只 3 条失败 → coldstart 无料 → 0 规则。
- 教训：golden 需要混合数据 + 足够数量，goodcase 不只给回归用，也是给 golden 校准判定基准。
